# app02 — Spatial Glass Deck & Detached HUD

## HTML sandbox · Three instruments, one active plane

Make VoxPocket feel like choosing a physical instrument from a shallow pocket: capture, actions, memory. This candidate is about **lateral movement and retained spatial position**, not app01's deep drawer, app03's optical mode replacement or app04's source/action stream. iPhone starts with exactly the frozen r3/v02 canvas; only Fold reveals the solid deck. macOS starts with a small detached HUD that can snap between four safe corners, then opens a two-column workbench with no navigation sidebar. Every destination is usable, every apparent control has a consequence, and no card exists merely for visual effect.

Stage 1 produces this complete design prompt, not code. Stage 2 implements a self-contained HTML approximation using synthetic content only. Coordinates: **VS-003 Precision Acoustic & AI Studio remixed with VS-005 Zen Paper Checklist**, **CL-006 Luminous Paper with CL-003 Sonic Cyan accents**. Design dimensions: layout-navigation, glass-material, motion-interaction, color-palette. X-Y-Z: **X** one foreground action, secondary navigation on the pocket handle, filters and configuration folded; **Y** three solid destinations overlap in depth and only one unfolds; **Z** background aura separate from functional glass handles, sharp solid card faces in front, overlaid settings/receipt above all. Never make text translucent just because the name contains “Glass Deck”. No AppTheme winner is selected here.

### The detached macOS instrument and its workbench

In the outer **1280×800 traffic-light window bezel**, fill the entire inner viewport with a synthetic quiet desktop surface. Do not draw extra traffic lights, browser chrome or an inner device frame. Initial HUD is **232×92**, at x=1024,y=684 (24px bottom/right inset). Its optical shell is a continuous 26px squircle with seven bars, one 32px hold control and compact intent/shortcut labels. Grabbing a dedicated 32px drag handle moves the HUD within safe bounds; release snaps to the nearest corner with 24px padding. Provide a native context menu “左上 / 右上 / 左下 / 右下” as the keyboard/non-drag equivalent. Its chosen corner survives workbench trips. This menu is actual app placement, not an outer gallery platform control.

Include a small MenuBar icon/action within the synthetic desktop scene for reopening it, with a proper accessible name.

The workbench is **two columns**: active canvas 900px, inspector 380px. No fixed sidebar. A 44px native window action toolbar selects Capture / Todo / Notes through a labeled route menu and offers Back and “返回 HUD”. Content begins 28px below the toolbar with 32px outer padding. The left canvas gives the active instrument a wide, unbordered solid face; a horizontal **destination menu** in the toolbar is native app navigation, not a persistent mobile bottom bar. The right inspector uses L1 opaque color and a single subtle vertical luminance seam, no nested glass card. Selecting Todo binds its detail here; selecting Notes binds its preview. Detail's Run/Notes Convert becomes the one P0 while inspected; the previous canvas P0 is demoted, not duplicated. When no object is selected, the inspector collapses its contents to “选择一项查看详情” without dummy metrics. Model settings attach as a sheet; runner anchors to the selected object's receipt action. Main capture uses a top-trailing hold control, not a stretched iPhone dock. “返回 HUD” hides the workbench and restores its previous HUD corner, state and Done sentence; “打开工作台” restores route, inspector selection and list scroll.

### Material sample and typography specification

Use **-apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text"**, then sans-serif, for every native label. Root sentence retains 25/650/33.75. Deck mobile title/focus 30/650/36; body 17/450/25; label/navigation 15/550/21; metadata 12/500/17. Desktop title 26/600/32; body 13/450/20; toolbar 13/550/18; HUD cue 11/500/16. Do not exceed four sizes per pane. Use tabular numbers for elapsed time, receipt progress and counts, normal text metrics elsewhere. Avoid decorative all-caps headings and fixed-height text boxes. Natural CJK wrapping is mandatory; numbers and labels never truncate with an ellipsis. Use 4px atoms, 20px page padding, 24px section spacing, 40px above the focus object in its card. Compact HUD padding 12px, internal gap 4px; two-column workspace structural gap 32px. Container padding is never less than the row spacing.

Status always includes words or paths, never color alone. Apply the same rising luminance polarity in both appearances; no white note cards in dark mode. Keep 90% neutral; only one primary/selected accent family per pane. Check normal text at ≥4.5:1 and large text at ≥3:1 against resolved solid backgrounds.

The **optical shell is not the card content**. Put a soft, nonrepeating radial cyan/ice-blue aura on the desktop backdrop behind the HUD or on the canvas behind the pocket handle (blur 40px, opacity .16 light/.12 dark). The shell is white/.28 light or #263D4D/.56 dark, with **blur(28px) saturate(190%)** for both standard backdrop-filter and **-webkit-backdrop-filter**. Adjacent glass belongs to one sampling container, never nested glass-on-glass.

### Gesture/state score and failure edges

Idle → Listening begins on pointer-down, with pointer capture and a changing synthetic transcript in the existing sentence. Seven bars move with seven distinct phase offsets; no microphone, audio input, AudioContext or real media access. Release → Refining for 900ms, with bars resting and readable progress in the inherited feedback area. Done shows “整理发布决定，确认下一步行动。” and commits voice_capture once; Todo intent creates a draft awaiting the same explicit decomposition/review flow, never starts a runner automatically. The HUD uses the identical logical recorder state but its own compact layout. Pointercancel, lost capture, page visibility loss, window blur or Escape before commit cancels, clears pending timers and returns to Idle with no synthetic note saved. Reject repeated presses during Refining; suppress the click following pointer-up.

Focused Space down/up supplies hold/release; Enter/assistive click toggles start/stop for non-hold access. ⌥Space / ⌥⇧Space operate while this page is focused and outside editable fields, not globally in macOS. Ignore repeat keydown. Closing a deck/HUD during an uncommitted capture cancels first. A new capture from Done retains old committed notes. Waveform loops, spatial transforms, snapping springs and card motion vanish with prefers-reduced-motion; route selection becomes instantaneous or ≤100ms fade, seven static unequal bars remain as state. No constant idle floating animation.

Completion keeps its task ID and shows “已完成 · 可撤销” with a 5-second Undo. Repeat decomposition never adds another three rows. Run goes 已接收 → 执行中 → 已完成 through deterministic 600ms simulated ticks, with manual refresh able to advance without double-committing. Retain receipt when navigating away and back. If a local operation cannot complete, present an inline retry action; never imply an unreachable real server. Empty queue and no-result Notes use one message plus a relevant capture/clear-filter action. No fake disabled empty panels full of placeholder stats.

Escape unwinds in order: uncommitted recording, top runner receipt, settings, front-card detail, deck, then idle HUD. Sheet bodies scroll independently; the iPhone home-indicator area has 34px interaction clearance. Mobile settings detents have actual height/max-height 45vh/80vh and an accessible Expand/Collapse action, not only drag. Focus is trapped in modal layers and restored to the exact opener. Dragging over a task does not navigate the deck; HUD drag cannot accidentally start recording. At 200% text size switch fixed card body height to internal scrolling, never crop a title, shrink the font or widen the viewport.

Keep both outer-host paths: inherited same-origin parent **postMessage** `rich-theme` with theme light/dark and `rich-platform` with platform phone/desktop, mapping mobile/macos aliases internally. Validate event.source===parent and origin, with file: null only for local preview; unknown payloads do nothing. Also honor direct data-theme changes on documentElement/body from gallery-chooser and resize as a platform fallback. No inner platform/theme/selection widgets. Switching platforms maps the logical current route, selected note/task, card history and receipt to the desktop canvas/inspector; it never duplicates a note or resets progress. Preserve optional rich-nav notifications if supplied by the host. The chooser owns stars and candidate selection, never this native app canvas.
