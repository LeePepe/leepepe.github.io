# v03 — Spotlight-Style Voice Command Bar

Imagine a precise optical search instrument which accepts a spoken intention instead of a query. Its architecture is a centered horizontal command bar with a progressively revealed command list, not an orb, dock or miniature document window. Keep the mandated Spotlight identity and explicit Text/Todo intent routing. Every interaction below is local and synthetic.

## Opening frame and command grammar

At 1280×800, make the page fill `100vw × 100vh` inside the outer macOS traffic-light bezel; never redraw that bezel. A 680×84px bar sits at x=300, y=218 with a 24px continuous corner radius. Capture microphone at x=324..372, the intention field at x=392..844, and a subordinate disclosure at x=916..956. The single P0 is the intention/capture field as one compound control, not separate equally weighted Text and Todo buttons. “Say what comes next” is the Idle line. On the second line of the field show “Option+Space · Text” and “Option+Shift+Space · Todo”; “Escape · Cancel” appears at its trailing end during capture. These are native product key hints, not gallery buttons.

The bar's lower edge can reveal one 680×228px opaque command list at x=300, y=314; six rows at 36px with 6px vertical padding. The six exact commands are “Text capture”, “Todo capture”, “Recent notes”, “Open workspace”, “Copy last note”, and “Refinement settings”. There is only one list: selecting Text or Todo changes intent; selecting Recent notes replaces it with history, and Refinement settings opens a compact anchored popover. Open workspace performs the expansion below; Copy last note is disabled with an explanation until a Done note exists and then uses the explicit Copy behavior below. `Command+J` toggles this list. Idle initially keeps it folded so the field is the only focal region. No persistent sidebar or bottom bar. P1 intent and recents fold in this list; P2 settings fold in the anchored popover. “Type a command” is a real keyboard fallback: typing text in the field filters these commands locally, never searches a service.

Workspace expansion uses the same centerline and width but changes topology. The Done row offers “Open workspace”; `Command+Return` reveals an opaque 880×580px region x=200, y=112. The bar becomes a 48px native action toolbar at its top, and the selected document occupies a left 560px reading column with a 256px trailing intent inspector, separated by 16px space and 24px outer padding. Inspector starts folded; a toolbar disclosure shows it. Back / `Command+[` restores the command bar and the current result. The previous list's selected row is restored, not reset. No fake website navigation.

## A complete spoken command

`Option+Space` starts Text capture and `Option+Shift+Space` starts Todo capture, only while the page has focus. Bind physical Space plus modifiers, capture intent once, ignore repeated keydowns, and stop on Space keyup even when modifiers are no longer held. Do not pretend HTML owns a global macOS shortcut. Pointer hold on the main capture region follows the same sequence; a focused button's Enter/Space activation offers a toggle start/stop path for users who cannot hold.

Idle → Listening widens the field's baseline into seven vertical round-ended bars (width 3px, gap 4px, maximum heights 5/10/18/26/18/10/5px). Synthetic transcription streams in at 180ms word intervals: “Remind me to outline the sample guide, review the examples, then share a draft.” The intent caption changes to “Text capture” or “Todo capture”; seven bars remain feedback only, not a second button. A small timer uses tabular 00:01.

Release → Refining keeps the bar's width stable and changes the field to “Interpreting your intention” for 750ms. Seven bars settle to 5px, all dispatch controls are disabled to prevent duplicates. Done in Text mode shows “Outline the sample guide, review its examples, and share a draft.” Its sole P0 becomes “Copy note.” Done in Todo mode produces one “Prepare the sample guide” task. The result list shows three folded substeps, “Outline the guide”, “Review examples”, “Share a draft”; `ArrowRight` on the task row expands them and `ArrowLeft` folds them. P0 becomes “Add 1 task.” These are deliberate explicit commits, not automatic AI execution.

List navigation: Up/Down changes the single highlighted command; Return commits that row and returns to the field, except a Done result's Return performs Copy/Add. Escape from the command list closes it and restores field focus. The input's text cursor retains ordinary editing arrow behavior; arrow-based list navigation takes over only when the list is explicitly open, announced with combobox expanded state and active descendant. `Command+Return` always opens workspace at rest, never commits twice. Copy must visibly report “Copied sample guide note”; if clipboard unavailable, select the result and explain “Text selected; press Command+C.” Add creates exactly one in-memory task with circular semantic-button completion rings. The inspector explains the chosen intent and raw source without rendering duplicate raw source alongside the same raw list. `Command+Z` undoes the last Add.

Escape during Listening or Refining invalidates the capture token, clears delayed word/refinement callbacks, restores the prior Done state or Idle and announces “Capture cancelled.” Pointercancel/lost capture, page hide and blur also cancel, while an ordinary pointer release outside the field ends capture through pointer capture. Ignore generated click after hold; do not let keyboard repeat create new runs. Navigation and intent changes cannot mutate an active run. A local “Retry refinement” action appears if a seeded failure is chosen in the settings popover; preserve raw words until successful retry. No destructive operation is hidden behind Escape.
