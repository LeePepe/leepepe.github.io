## Voice routing and execution receipts
Idle capture label names the currently active project. Hold>=180ms enters Listening; release enters Refining for1000ms; Done shows a proposed project and exactly3 child action items. Tap/Enter toggles Listening/stop; held focused Space supports hold/release. Ignore repeat keydown, suppress click after hold. Synthetic utterance: “为星港演示写发布说明：收集三项变化，写简短说明，检查用词”. Preview project is VP. Children exactly “收集三项示例变化”, “写一段发布说明”, “检查说明的用词”. The project field is a real menu in the preview; changing it changes the new record's lane only, not the words. “加入项目” creates one parent/three children once, selects its project, and leaves original P0 unchanged. Selected-task “语音拆解” uses update-parent context with “应用三步”; replacing children requires confirmation. No fourth summary child or duplicate inserts.

Cancel/Escape, pointercancel, lost capture, leaving the page or cancel during Refining discards draft routing/children, invalidates late callbacks and restores Idle. Done supports rerecord/discard. Everything uses local fixture data; no microphone, network or personal data.

Inside detail, runner offers a clear “运行三步” text action. Show provider labels “Herdr · 模拟调度” and “Claude · 模拟执行” only as a contextual execution receipt, never falsely live-connected. States: 待命 → Herdr 排队(300ms) → Claude 第1/3步 → 第2/3步 → 第3/3步 → 完成, 800ms each. Stop pauses; Continue resumes, Retry resets runner progress without completing tasks. A deterministic “示例阻塞” choice in receipt overflow presents a plain reason and retry; it is not global debug chrome. Receipt timestamps are synthetic fixed relative durations, tabular and never clipped. Only the currently running record has one live status line; no repeated neon badges.
