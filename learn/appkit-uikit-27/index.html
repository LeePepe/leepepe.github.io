macOS 27 AppKit 与 iOS 27 UIKit 现代化：自由缩放窗口、同心圆角与手势革命

iOS 27 让 iPhone 窗口在 Mac 镜像与 iPad 上任意拉伸（UIScreen.main、idiom 与 orientation 彻底失效）；macOS 27 AppKit 告别 mouseDown 阻塞循环，拥抱 NSControl.Events 与容器同心圆角。

2026 年 11 月 9 日·约 5,600 字·阅读约 10 分钟

一句话结论：OS 27 彻底打破了「iPhone 屏幕固定不可调」与「AppKit 必须手写 mouseDown 循环」两大历史假设 —— 在 iOS 27 中，iPhone 应用在 Mac 镜像与 iPad 上全面支持自由窗口拖拽缩放（UIScreen.main、userInterfaceIdiom 与 interfaceOrientation 布局判断正式宣告失效）；在 macOS 27 中，AppKit 全面转向 Gesture Recognizers + NSControl.Events + NSView.cornerConfiguration 同心圆角。

核心教具与量级速览#

核心痛点问答#

Q1. 为什么我的 iPhone 应用在 macOS 27 的「iPhone 镜像（iPhone Mirroring）」或 iPad 上把窗口拉宽后，界面还是挤成细长一条，甚至横竖屏判断全乱了？#

  • 直答：因为你在代码里用了 UIScreen.main、userInterfaceIdiom 或 interfaceOrientation 做布局判断——在 Mac 镜像下，哪怕窗口被拉成 16:9 宽屏，它的 idiom 依然是 .phone，它的朝向依然是 .portrait！
  • 原理与教具：WWDC26 Session 278（01:25–08:36）重申了 WWDC14 Bruce Nilo 的名言：「设备旋转只不过是一次带动画的 Bounds 变化（A device rotation is only an animated bounds change）」。在 OS 27 中：
    1. 拆掉 UIScreen.main：算布局空间直接看 view.bounds.size（或在 UIWindowSceneDelegate 中实现 windowScene(_:didUpdateEffectiveGeometry:) 读取 windowScene.effectiveGeometry.coordinateSpace.bounds）；算像素倍率直接在 layoutSubviews() 里读 traitCollection.displayScale（系统自带 Automatic Trait Tracking，跨显示器拖拽窗口时会自动重调 layoutSubviews）；
    2. 拆掉 idiom 和 orientation 布局分支：一律改用 horizontalSizeClass / verticalSizeClass；甚至 iPhone 应用现在也能通过 tabBarController.sidebar.preferredPlacement = .sidebar 在拉宽成 Regular Size Class 时自动展开为侧边栏！
    3. 陀螺仪与指南针零换算对齐：在 iOS 27 中，UIView 直接遵循了 CoreMotion 和 CoreLocation 的 Body 协议。只需在 viewDidLoad() 里写 motionManager.deviceMotionBody = view 和 locationManager.headingBody = view，不管窗口怎么缩放旋转，传感器数据永远自动对齐当前视图坐标系。

Q2. 在 macOS 27 AppKit 中，为什么苹果强烈建议删掉自定义的 mouseDown: 重写？如果兄弟视图挡住了点击、或者要在自绘视图里做文字选择怎么办？#

  • 直答：因为現代 Mac 应用往往是 AppKit + SwiftUI 混编，Gesture Recognizers 才是三端通用的唯一事件语言；按钮追踪请用全新引入 AppKit 的 NSControl.Events，自绘文本选择请用 macOS 27 全新的 NSTextSelectionManager。
  • 原理与教具：在 WWDC26 Session 289（01:27–05:49）中，Ujjaini 给出了完整替代矩阵：
    1. 告别为监听松手位置而子类化 NSButton：以前为了知道鼠标是不是移出按钮外才松开，必须子类化 NSButton 重写 mouseDown；现在直接用从 OS 10.11 回溯开放的 NSControl.Events：
      SWIFT
      let button = NSButton()
button.addTarget(self, action: #selector(trackingEndedOutsideHandler), for: .trackingEndedOutside)
    2. 自绘视图秒获原生文本选择：macOS 27 新增 NSTextSelectionManager，只需挂载到任意自定义 NSView 并提供数据源，即可免费获得双向文本高亮、拖拽文本等全套原生体验；
    3. 透明覆盖层不挡点击：因为手势识别器作用在视图层级上，如果上层有个装饰性兄弟视图叠在按钮上，会静默吞掉点击——只需在该覆盖层重写 override func hitTest(_ point: NSPoint) -> NSView? { return nil } 即可让点击穿透。

Q3. 为什么我的 Mac 应用在系统夜间自动更新重启时总是卡住系统弹窗报错，或者重启后窗口状态全丢了？#

  • 直答：因为你的非关键 Sheet 默认开启了 preventsApplicationTerminationWhenModal = true 拦住了系统退出，且未正确实现 NSWindowRestoration 的 invalidateRestorableState() + 必调 completionHandler 契约。
  • 原理与教具：在 Session 289（08:57–14:06）中，打造“像从未退出过一样”的 Mac 连续性只需两步：
    1. 放行非关键模态框：只有“未保存文档确认框”才需要阻止退出；对于普通设置面板或预览 Sheet，务必设置 window.preventsApplicationTerminationWhenModal = false；
    2. 按需标脏 + 有问必答：开启 window.isRestorable = true 后，AppKit 不会每帧去调 encodeRestorableState(with:)，只有当你在侧边栏切换选中项并主动调用 self.invalidateRestorableState() 时，系统才会在稍后空闲时去保存 ID（切记只存轻量 UUID，别把整个数据库塞进去！）。而在重启恢复 restoreWindow(withIdentifier:state:completionHandler:) 时，即便窗口创建失败也必须调用 completionHandler(nil, error)，否则 AppKit 会一直死等该窗口。

Q4. macOS 27 和 iOS 27 在 Liquid Glass、同心圆角与 Apple Intelligence（Siri 拖拽）上有哪些必须注意的新细节？#

  • 直答：AppKit 新增了 NSView.cornerConfiguration 容器同心圆角 与 玻璃点击微弹跳；UIKit/AppKit 菜单栏默认隐藏次要图标；且 Siri 会通过后台无手势调用拖拽代理抓取上下文，严禁在 sessionWillBegin 里弹动画或模态框。
  • 原理与教具：
    1. AppKit 容器同心圆角（Session 289 15:41–16:54）：自定义视图靠近窗口四角时，只需重写 cornerConfiguration，系统会根据它离窗口边缘的距离自动计算同心圆角半径：
      SWIFT
      class LocalWeatherView: NSView {
   override var cornerConfiguration: NSViewCornerConfiguration? {
       let radius: NSViewCornerRadius = .containerConcentric(minimumCornerRadius)
       return .uniformCorners(radius: radius)
   }
}
    2. Siri 静默借道 Drag & Drop（Session 278 12:56–14:05）：在 iOS 27 中，当用户在菜单里点“Ask Siri”时，Apple Intelligence 会直接调用你已实现的 Drag Delegate 方法来提取屏幕内容！因此 sessionWillBegin 可能在没有任何手指触摸的情况下被系统触发——把所有拖拽起手动画或状态 UI 全部移到 sessionDidMove 中，避免灵异弹窗。

立即可用清单#

  • 用 Device Hub 与 Xcode 27 Live Previews 做「自由拉伸压力测试」：打开 Xcode 27 Previews 或全新的 Device Hub 应用，点击“Enter Resize Mode”随意拖拽 iPhone 窗口边缘；全局搜索并清零 UIScreen.main、userInterfaceIdiom 和 interfaceOrientation 布局代码（或直接唤醒 Xcode 27 内置的 App Modernization Agent Skill 自动重构）。
  • 给 AppKit 窗口补齐三行现代配置：打开主窗口控制器，加上 window.autorecalculatesKeyViewLoop = true（自动维护 Tab 键盘焦点环）、非阻塞 Sheet 加上 sheetWindow.preventsApplicationTerminationWhenModal = false、贴边子视图重写 cornerConfiguration 启用 .containerConcentric。
  • 检查拖拽代理与滚动边缘：把 UIKit 拖拽代理 sessionWillBegin 里的 UI 副作用移到 sessionDidMove（兼容 Apple Intelligence 无手势提取）；删除以前硬编码的 .soft 滚动边缘样式，恢复 .automatic 让 OS 27 全新高清滚动边缘自动生效。

延伸视野#

  • 设备边界的消融与 Agentic Coding 的原生化：当 iPhone 应用可以在 Mac 桌面上自由拉伸、可以展开成侧边栏、可以被 Siri 直接通过拖拽协议读取实体时，“手机应用”与“桌面应用”的物理藩篱已经彻底消失。更值得注意的是，Apple 在 WWDC26 首次将官方迁移经验打包成可通过 xcrun agent skills export 导出的 Markdown Agent Skills——框架演进本身，已经开始为 AI 编码代理提供一等公民的结构化知识弹药。
