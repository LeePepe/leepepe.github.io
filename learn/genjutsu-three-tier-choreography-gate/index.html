Genjutsu：三尺度视觉编排（cast/paint/bunshin）、风格化视觉生成控制与跨平台契约门禁

Genjutsu 管住 AI 视觉与动效不翻车的核心，不是写更长的形容词 Prompt，而是按「单交互（cast）→ 整套风格（paint）→ 整站多代理（bunshin）」三级尺度锁定审批粒度，并用字节级共享块校验 + 真实渲染截图回执（shoot.mjs）替代「只读代码不看画面」的盲审。

一句话结论：Genjutsu 管住 AI 视觉与动效不翻车的核心，不是写更长的形容词 Prompt，而是按「单交互（cast）→ 整套风格（paint）→ 整站多代理（bunshin）」三级尺度锁定审批粒度，并用字节级共享块校验 + 真实渲染截图回执（shoot.mjs）替代「只读代码不看画面」的盲审 —— 在覆盖 3 大平台族、6 个目标端、736 个 API 符号的规模下，把单模块上下文严格封顶在 25,000 字符以内。

核心教具与量级速览#

抽象概念 / 参数关键数字生活教具 / 直观参照物理/工程效果
三级编排尺度（cast / paint / bunshin）从 $1.53 / 23 轮（单交互）到 10.5M Token（7 页整站）拍短视频特写 vs. 定美术设定集 vs. 剧组多机位拍长片防止杀鸡用牛刀；进入高成本 bunshin 前必须先报预算并过 2 道人工拍板门禁
11 点跨文件同步锁（check-shared-blocks.sh）3 个编排器 × 4 个守卫区（7 处） 字节级一致三联复写纸（改一页必须三页字字对齐）杜绝不同入口的扫描、加载、审计规则在迭代中各自漂移
单次内联加载上限（validate-skills.py）每个模块与 load_ref 引用硬上限 25,000 字符登机随身行李尺寸框（超 30,000 字符会被宿主截断）保证单次 Shell 读取 100% 完整送达模型上下文，不发生静默截断丢规则

核心痛点问答#

Q1. 为什么用 AI 生成风格化视觉与动效时，要么「改一个小按钮却把全站配色掀翻」，要么「做整站却漏掉一半页面状态」？#

  • 直答：因为没有把「单点交互微调」「整套视觉系统」「多页面整站工程」拆成正交的审批回路；Genjutsu 通过 cast（原 uchiha 单交互）→ paint（原 kuchiyose 整套视觉与 MASTER.md）→ bunshin（多代理整站编排） 严格隔离作用域与审批门禁。
  • 原理与教具：就像装修房子——
    1. cast（换一个阻尼门把手）：只针对单一界面动作提炼 1 条交互命题（Interaction Thesis），渲染带重播按钮的预览获批后直接落代码（单次约 $1.53）；
    2. paint（全屋软装色彩设定）：先问清“保留旧品牌 / 局部改 / 推翻重做”，产出视觉命题 + 交互命题 + 跨组件 MASTER.md 令牌系统；
    3. bunshin（总包施工队建整栋楼）：先明示 Token 成本，强制经过 Tier 确认 + 视觉方向确认 两道人工门禁，再由艺术总监（Art Director）调度「每页 1 个 Builder + 独立 Reviewer + 止损轮次上限」。

Q2. Genjutsu 如何控制风格化画面与复杂连续动效（如昼夜天象渐变、陶艺烧制曲线），避免生成千篇一律的 AI 塑料感？#

  • 直答：强制要求「视觉元素绑定真实结构化数据源 + 显式标注未验证项（Receipt Honesty）」，绝不允许凭空捏造装饰卡片或假数据。
  • 原理与教具：在 Nocturne 天象馆案例中，画面没有用随机 CSS 噪点冒充星空，而是直接读取 data/stars.json 中里斯本 22:00 真实的 403 颗恒星与土星坐标，随滚动将地平线从暮蓝压暗至纯黑并按星等依次点亮；在 Étale 潮汐案例中，每一条曲线均来自 NOAA 真实潮汐数据并标注站点与日期。更重要的是，它的运行回执（receipt.md）强制诚实记录缺陷：只要无头运行没做实机截图对比，就必须在回执上打上 UNVALIDATED 烙印，绝不把“代码编译通过”谎报为“视觉验收通过”。

Q3. 当技能库同时支持 Web、Android Compose 和 Apple SwiftUI（共 736 个 API 符号）时，如何防止规则腐化或漏检？#

  • 直答：用 PLATFORM-CONTRACT.md 的 10 问准入清单 + check-shared-blocks.sh 的 字节级三端同步锁 + 25,000 字符硬上限把维护成本关进笼子。
  • 原理与教具：维护跨端设计技能最怕“改了 A 忘了 B”。Genjutsu 要求任何平台家族入库必须回答 10 个硬问题（如何从磁盘文件识别技术栈、Reduce Motion API 是什么、哪些属性严禁动画、如何用精确工具菜单测量 16.67ms 掉帧、版本敏感断言记在哪里等），并将 scan、load、audit、preview 四大区块在三个编排器之间做字节级比对——只改一处 CI 当场拒绝。

Q4. 为什么 bunshin 宁可在 SwiftUI / Compose 上主动降级回 paint，也绝不在缺少「静态截图测试台（Evidence Harness）」时强行跑多代理整站循环？#

  • 直答：因为没有真实渲染截图回执（shoot.mjs）时，Reviewer 只能“读代码脑补画面”，多代理评审循环会瞬间退化成昂贵的文字游戏。
  • 原理与教具：就像蒙着眼睛评判画展——不看画布只看颜料配方表，根本抓不住“1100px 宽度下星表文字压住穹顶”或“手机端面板遮挡底部”这类真实几何碰撞。因此 Genjutsu 立下铁律：任何新平台接入 bunshin 前，必须先具备免开发服务器启动、固定视口截图、控制台报错捕获以及带 --self-test（证明测试台自己能抓出失败）的 Evidence Harness。

立即可用清单#

  • 按改动半径三档选型：单组件手感用 cast 级单命题快审；单页/全 App 换肤先冻结 design.md / MASTER.md（paint 级）；跨页整站重做才启动多代理并发并预设止损轮次（bunshin 级）。
  • 无截图不宣称 UI 审查通过：凡涉及视觉样式、折行与图层遮挡，Reviewer 必须基于真实视口渲染截图（如 390px 移动端与 1280px/1440px 桌面端）做 Visual Traceback；未跑真实画面对比的项必须在回执中显式标注未验证边界。
  • 给跨技能共享块加字节级同步校验：将多入口共用的扫描、加载与审计表抽成受检区块，并将单份 L2 参考文件控制在 25,000 字符以内，防止宿主静默截断。
